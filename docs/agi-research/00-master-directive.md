# 2. PROJECT CONTEXT — DARK AGI

DARK AGI is an evolving security operations and autonomous engineering platform running on Windows.

Its long-term direction is to become a research and engineering environment capable of understanding complex problems, planning investigations, creating tools, executing experiments, analyzing results, and improving its own workflows.

It currently consists of two separate repositories.

### Backend Repository: dark-agi-backend

The backend is the authoritative execution and security control plane.

Responsibilities include:

- REST API under /api/v1
- Execution engine
- Operation registry
- Input validation
- Scope enforcement
- User authentication and authorization
- Approval workflows
- Task queue
- Tool adapters
- Remote host governance
- Audit logging
- Findings and evidence management

The backend is the ultimate authority for security decisions.

### Frontend Repository: dark-agi-frontend

The frontend is the operational and intelligence interface.

Technology stack:

- Next.js 16
- React 19
- TypeScript
- Tailwind CSS 4
- SWR
- Vitest
- openapi-typescript

The frontend must consume backend APIs through generated OpenAPI types.

Important: Next.js 16 introduces breaking changes. Before implementing Next.js-specific functionality, inspect the documentation available inside:

node_modules/next/dist/docs/

Do not assume older Next.js APIs remain compatible.

### Existing Platform Capabilities

DARK AGI already has an architecture based on:

Operation → Job → Approval → Execution → Results → Findings / Evidence.

Its command language uses:

The platform includes security operations involving:

### Architectural Non-Negotiable Rules

1. The backend remains the authoritative security enforcement layer.
2. The frontend must never be trusted to enforce authorization.
3. Scope restrictions must never be silently bypassed.
4. Approval requirements must remain enforceable.
5. AI agents cannot grant themselves additional permissions.
6. Tool execution must use registered adapters and validated inputs.
7. Remote execution requires registered hosts, credentials, and authorization.
8. Audit records must remain verifiable.
9. Experimental development must not silently weaken production security controls.
10. High-impact operations require explicit authorization and appropriate human approval.

DARK AGI must evolve without sacrificing these foundations.
